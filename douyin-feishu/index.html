WHAT TO LEARN

GitHub 内容最值得学的
三种方法

01

一句话把价值说清

项目名、首屏副标题和第一段 README 先回答：给谁用、解决什么、为什么现在就要试。

02

让第一次运行变简单

安装命令、Quick Start、截图和 Demo 不是装饰，它们决定用户会不会从“收藏”走到“运行”。

03

用证据代替形容词

功能列表之后紧跟示例、命令、架构和真实输出，让“强大”变成可以检查的东西。

METHOD CARD / 02

把一个 GitHub 项目
拆成 5 个动作

01写一句能被转发的定位“给谁 + 解决什么 + 用什么方式”写在 README 第一屏，不要先写团队故事。
02把 Quick Start 放到前面安装命令、环境要求、最短运行路径，直接让用户完成第一次成功。
03用 Demo 证明不是 PPT放截图、录屏、示例输入和输出，让读者在安装前就知道结果长什么样。
04把功能改写成场景不要只列 feature；写成“你遇到 X 时，用这个命令完成 Y”。
05把边界写在明面上许可证、依赖、数据来源、隐私和商业限制，写清楚反而更容易建立信任。
